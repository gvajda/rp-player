# Key technical decisions (non-obvious, not in code)

Notes here capture behaviour and design rationale that cannot be derived from reading the code or git history. Source of truth for the project-level architecture is still `docs/DESIGN.md`; this file is the running log of decisions made during PR work.

---

## Audio pipeline

- **Hog mode is owned by**`HogModeController` (`Sources/RPPlayer/Audio/HogModeController.swift`), not mpv. The actor writes `getpid()` to `kAudioDevicePropertyHogMode` via `AudioObjectSetPropertyData` BEFORE mpv opens the device. mpv is configured with the plain `coreaudio` AO and `audio-exclusive` is never set. This bypasses mpv's `coreaudio_exclusive` AO format-negotiation failures observed on USB DACs (Qudelix-5K and similar). `AppContainer.live()`'s settings binder calls `acquire(deviceUID:)` / `release()` based on `(hogModeEnabled, outputDeviceUID)`. `release()` runs on app termination so the device returns to shared use. The engine has no `setHogMode` method and no `hogModeChanged` event — the libmpv-owned hog era is fully gone. Additionally, `acquire(deviceUID:)` reads and stores the device's pre-hog nominal sample rate, then sets it to 44100 Hz after confirming exclusive ownership (`setSampleRateInternal` with a 50 ms settle); `releaseHog` restores the original rate (no settle — no IO will open on the release path) and clears the stored value. This ensures RP's 44.1 kHz streams play through the hardware without CoreAudio resampling even when the device was previously configured at 48 kHz or another rate.
- **Release-on-pause** (`AppSettings.releaseHogOnPauseEnabled`, default true) hooks `HogModeController.acquire` / `release` to coordinator state transitions. AppContainer subscribes to `coordinator.stateUpdates` (new `AsyncStream<PlaybackState>`); on `.playing` it acquires hog (when both settings are on), on `.paused`/`.stopped` it releases. Initial launch skips hog acquire when release-on-pause is on — no point grabbing the device before the user clicks play. The settings binder also reads `coordinator.currentPlaybackState` to decide whether to acquire on a pure settings change while paused.
- **Volume mode** (`AppSettings.volumeMode: VolumeMode`, default `.none`; per-device via `AudioProfile.volumeMode`) is a 3-state enum replacing the legacy `forceMaxVolumeEnabled` + `applyReplayGainEnabled` bool pair (PR 34). Cases: `.none` (clean signal — no normalization, no pin), `.replayGain` (mpv `replaygain=track`), `.forceMax` (mpv `volume=100, volume-max=100` + CoreAudio device volume pinned to 1.0 via `DeviceVolumeController`). Mutual exclusion is encoded at the type level — the previous `effectiveRG = applyRG && !forceMax` calculation collapses to `volumeMode == .replayGain`. UI is a 3-Button row (`volumeButton(.none)` / `volumeButton(.replayGain)` / `volumeForceMaxButton`) using `Button + StableButtonStyle(filled:)` — the same pattern as the Appearance / Menu bar icon / Popover style rows. `Picker(.segmented)` was tried first but rejected because its per-tag `.disabled` modifier is a no-op for segmented style on macOS 14, leaving Force Max clickable when hog is OFF (the binding-level guard silently dropped the click — confusing UX). Button-row pattern fixes this: `Button.disabled(!hogModeEnabled)` is fully honored. Force Max button's action handler fires the destructive-confirmation alert (hearing-damage warning) when current mode isn't already `.forceMax`; alert's Continue calls `setVolumeMode(.forceMax)`. A single `HoverInfoIcon` sits to the left of the buttons with a combined tooltip covering both ReplayGain and Force Max. The legacy JSON keys `forceMaxVolumeEnabled` / `applyReplayGainEnabled` survive in `CodingKeys` on `AppSettings` and `AudioProfile` for read-only migration on first decode (force-max wins on bool conflict); encoders never write them back. Hog OFF→ON ground-truth is demote-only: if `volumeMode == .forceMax` AND device volume < 0.999 on hog acquire, demote to `.none` — does NOT silently promote `.none → .forceMax` when the device happens to be at max (that bidirectional sync property of the old bool toggle is intentionally gone).
- **Cue is ignored — songs always start from beginning** (PR 31 + post-smoke-test). `LivePlaybackCoordinator.play(channelId:)` and `skipForward` sync-refetch fallback both pass `startSeconds=nil` to `engine.play`. The `head.cue` field on `GaplessSong` is preserved in the model but never used for seeking. Rationale: better UX to hear the full song; user can skip if not wanted. Server occasionally returns `cue >= duration` (cursor past song end) which would otherwise fail with mpv `-16`; ignoring cue avoids that recovery cycle entirely. `engine.play(url:startSeconds:)` still accepts startSeconds; the only caller that uses it is the PR 30 stall-watchdog retry which preserves the user's mid-song position when restarting due to network stall.
- **`engine.play` resets mpv `pause=false` before `loadfile`** (post-smoke-test fix). mpv's `pause` property is global and persists across `loadfile`/`stop`. Channel-change-while-paused used to silently hang because the new file loaded but mpv stayed paused; the engine now unconditionally sets `pause=false` on every `play(url:)` call, so `loadfile` always means "start playing".
- **No engine-side hog fallback.** `LivePlaybackCoordinator.handleEngineEvent` just logs `.error(message:)` from mpv. The earlier `isHogModeAcquisitionFailure` heuristic + `engine.setHogMode(false)` retry was a vestige of the libmpv-owned hog era and is gone. If `HogModeController.acquire` itself returns false (CoreAudio status non-zero), surfacing that to the UI is a follow-up.
- **Device-unplug (and all engine errors) are handled via `fileEnded(reason: .error(code:))`.** `handlePlaybackError(code:)` cancels the refetch task, clears all queue/position/channel state (`queue`, `currentResponse`, `lastStartedEventId`, `currentPositionSeconds`, `pausedAt`, `pausePositionMs`, `currentChannelId`), and yields a message to `errors: AsyncStream<String>`. Code -14 (`MPV_ERROR_AO_INIT_FAILED`) → `"Audio device unavailable. Check System Settings → Sound → Output."` Any other code → `"Playback stopped unexpectedly (error \(code))."` The preceding `.error(message:)` log events remain log-only. The `errors` stream is single-subscriber (one continuation, finished in `shutdown()`); the VM is the sole subscriber.
- **`MiniPlayerViewModel.showPopoverIfNeeded`** is a public settable `@MainActor () -> Void` closure (default noop). `AppDelegate` sets it to `statusItemController?.showPopoverIfNeeded()` after both objects are created — this late-binding pattern breaks the `StatusItemController → PopoverController → MiniPlayerView → MiniPlayerViewModel` dependency cycle. The VM's errors subscription task sets `errorMessage`, `isPlaying = false`, `nowPlaying = nil`, then calls this closure on every error.
- **Bitrate label in the popover comes from `GaplessResponse.bitrateTitle` (the API field), not mpv.** mpv's `audio-bitrate` observer reported the decoded stream's running average — confusing because it lagged settings changes (still showed "AAC" after switching to FLAC). The whole observer pipeline is gone: no `mpv_observe_property("audio-bitrate", …)`, no `StreamFormat`, no `PlayerEvent.streamFormatChanged`. The coordinator threads `currentResponse?.bitrateTitle` through `NowPlaying.bitrateLabel` and `BlockBitrateLabel.display(_:)` surfaces it verbatim (trim + uppercase only). Confirmed integer→label mapping (exhaustive, from manual API enumeration): 0 → "32k aac", 1 → "64k aac", 2 → "128k aac", 3 → "320k aac", 4 → "flac", 5 → "128k mp3", 6 → "320k mp3". Display is still verbatim (trim + uppercase) — no switch table — so any future server-side renames appear automatically. `MiniPlayerView` renders `viewModel.currentBitrateLabel`.
- **Parametric EQ.** `AudioProfile.eqEnabled: Bool` (default false) + `AudioProfile.eqPresetName: String?` (filename reference, default nil; **not** an inline parsed preset). Presets stored verbatim as `.txt` under `~/Library/Application Support/RP Player/EqPresets/<name>.txt` via `LiveEqPresetStore` actor (`Sources/RPPlayer/Config/EqPresetStore.swift`). Parser (`EqPresetParser`) is strict — any warning (unsupported types LP/HP/NO/AP/BP, >10 bands, malformed `Filter N:` line) rejects the file. `OFF` filter syntax is silently skipped (intentional user state in the source format, not a defect). Filter chain via `mpv_set_property_string("af", ...)` (added on `PlayerEngine.setAudioFilterChain(_:)`) with FFmpeg lavfi graph `lavfi=[volume=<preamp>dB,equalizer=f=...:t=q:w=...:g=...,lowshelf=...,highshelf=...]`. Mid-playback safe (mpv applies dynamically without reopening). Composes orthogonally with hog mode, Force Max, ReplayGain. Bit-perfect claim lives in the Force Max tooltip ("Bit-perfect when EQ is off") — PR 34 already moved it.
- **EQ preset library is global, not per-device.** Multiple devices may reference the same `eqPresetName`. Deleting a preset surfaces a confirm alert listing referencing device UIDs (`SettingsViewModel.prepareDeletePreset(name:)`); on confirm, `deletePresetConfirmed(name:)` nil-outs every `eqPresetName` field that references it AND removes the file from disk. Export copies the stored .txt **verbatim** (preserves comments, `Xfeed:` lines, OFF filters, whitespace) — `EqPresetWriter` exists only for round-trip-from-parsed-form tests. Filename sanitisation rejects `/`, NUL, leading `.`, empty, ≥256 chars; UI's `NSOpenPanel` further constrains to `.plainText`.
- **EQ binder runs as a dedicated Task.** `AppContainer.runEqBinder(store:engine:eqPresetStore:initialProfile:)` is `internal static` for testability. The existing volume/hog binder loop has a per-iteration profile write-back (`s.audioProfiles[uid] = AudioProfile(...)`) — that constructor now threads `eqEnabled` + `eqPresetName` from the existing profile so non-EQ settings changes don't silently wipe EQ state. **Renamed in PR 36 to `runAudioFilterBinder` + `applyAudioFilterState`** when crossfeed joined the chain — see the Crossfeed note below.
- **EQ editing override (PR 39).** `EqEditingOverride` (`Sources/RPPlayer/Config/EqEditingOverride.swift`) is an actor that holds an optional `EqPreset?` representing the user's in-flight edit. `runAudioFilterBinder` subscribes to its `changes` stream alongside `ConfigStore.changes`; whenever the override is non-nil and the active profile has `eqEnabled = true`, `applyAudioFilterState` builds the lavfi chain from the in-memory draft instead of reading the on-disk preset file (no name match — by design, since presets are intentionally shared across devices). Why this exists: EQ presets are referenced by name (`AudioProfile.eqPresetName`) and the on-disk file is shared across every device that references it. Persisting keystroke-by-keystroke would write to disk on every stepper tick and flip the chain for every device sharing the preset; the override lets the editor stream a draft to the binder for live preview while the on-disk file stays untouched. Devices sharing the preset under edit cascade the live override intentionally (same preset name = same target headphone by project convention); a confirmation alert on Save makes the multi-device write explicit. The override actor lets the editor UI stream a draft to the binder for live preview while the disk file stays untouched until the user clicks Save or Save As. The override is cleared on editor dismiss (Cancel) and on every successful Save / Save As / Rename. `AudioFilterKey` (the previous Equatable key struct used to diff binder writes) is gone in PR 39 — the binder now diffs an override-aware tuple inline.
- **EQ parser/writer round-trip `OFF` rows (PR 39).** Previously the strict parser silently skipped `Filter N: OFF …` lines on load (treated as user-disabled-but-keep-in-file state); the writer renumbered surviving bands compactly so a load → edit → save cycle silently dropped OFF entries. Both ends now preserve the disabled state: parser maps `OFF` to `EqBand.enabled = false`, writer emits `Filter N: ON|OFF …` with sequential N over all bands (enabled + disabled). This is what lets the editor's Bypass dropdown work without rewriting the file shape — Bypass is just `enabled = false`. Filename cap was tightened from 255 to 30 characters in the same PR because the UI's preset-name label is the practical limit; imports longer than the cap truncate on first save.
### Skip low-rated songs — two-layer skip (PR 44)

Skip-bound songs (`SkipPolicy.shouldSkip`) are removed from the coordinator's
playback queue at every gapless-fetch ingestion point (Layer A) so their audio
is never downloaded, queued, or play-reported. A second check on the playing
head in `syncQueueHeadFromMpv` (Layer B) catches songs that entered the queue
before a mid-playback settings change and `skipForward`s past them. The Upcoming
list is a separate gapless fetch, so it still shows skip-bound songs (marked),
fetching only their album art. A fully-filtered block stops playback with a
user message rather than retrying.

- **Crossfeed (bs2b, PR 38).** `AudioProfile.crossfeedEnabled: Bool` (default false) + `AudioProfile.crossfeedProfile: CrossfeedProfile` (default `.cmoy`; cases `cmoy` / `jmeier` / `custom` after PR 38 UI-polish dropped the original `bs2bDefault` button) + `AudioProfile.crossfeedFcut: Int` (default 700, range 300...2000) + `AudioProfile.crossfeedFeedDb: Double` (default 6.0, range 1.0...15.0). Per-device only (no `AppSettings` top-level mirror — same shape as EQ). PR 36's `crossfeedStrength` / `crossfeedRange` (legacy ffmpeg `crossfeed` filter parameters) are gone; Codable migration on decode: legacy profiles with those keys migrate to `.cmoy / 700 / 6.0` defaults (no value mapping — the algorithms differ), and legacy `crossfeedProfile=="default"` strings (PR 38 alpha shape) remap to `.custom` + seed 700 / 4.5 (bs2b library's named-default values). Filter chain order locked at **Preamp → EQ bands → Crossfeed**: preamp stays at head to preserve AutoEQ headroom semantics (negative gain prevents EQ peak clipping); crossfeed sits at the tail so it operates on the equalized signal. `EqChainBuilder.build(_:) -> String?` was split into `buildParts(_:) -> [String]` (no `lavfi=[...]` wrapper) so `AppContainer.applyAudioFilterState` can concatenate the EQ parts + the single crossfeed fragment from `CrossfeedFilterBuilder.buildPart(profile:fcut:feedDb:)` into one `mpv af` write. The builder emits `bs2b=profile=<name>` for named profiles (cmoy, jmeier) and `bs2b=fcut=<f>:feed=<int>` for custom, where `feed` is in 10×dB units (e.g. 45 = 4.5 dB). The binder (`runAudioFilterBinder`) diffs a 5-tuple `AudioFilterKey` (eqEnabled / eqPresetName / crossfeedEnabled / crossfeedProfile / crossfeedFcut / crossfeedFeedDb) — only re-applies on a real change. Volume/hog binder's per-iteration profile write-back threads `existing.crossfeed*` through `AudioProfile.init` (alongside existing `eqEnabled` / `eqPresetName` passthrough) so non-crossfeed settings changes don't silently wipe crossfeed state. Vendored libmpv must be the `audio-encodersgpl` variant rebuilt with `--enable-libbs2b` — see `Vendor/libmpv/README.md` for the rebuild + rpath-rewrite procedure. UI: 3-button profile picker + conditional `crossfeedCustomFields` row shown only when `crossfeedProfile == .custom`; entering `.custom` from any other profile seeds fcut = 700, feedDb = 4.5 (`SettingsViewModel.setCrossfeedProfile` does the seed; re-selecting Custom while already Custom preserves the user's values). Custom row is right-aligned to the Custom button's column via full-width HStack + leading `Spacer(minLength: 0)` + trailing `Toggle("").labelsHidden().opacity(0).allowsHitTesting(false)` anchor (`.hidden()` was tried first but collapses layout for empty-label Toggles; opacity-0 always renders, guaranteeing identical width to the visible Toggle in the row above). No headphone auto-detection — user opts in per device.
- **`ClampedNumericField` validation contract.** `internal enum ClampedNumericFieldLogic` exposes 3 static helpers: `parse(_:locale:)` (locale-aware `NumberFormatter` with a `Double(trimmed)` dot-only fallback so canonical-form input works in any locale), `isValid(_:in:)` (rejects NaN + checks `range.contains`), `format(_:)` / `format(_:decimals:)` (default `%.2f`; PR 38 overload accepts an explicit decimal count). The view binds rawText to `@State` (NOT directly to `Double` — direct binding would silently revert and we'd lose the red-glow signal). `.onChange(of: rawText)` writes through to `value` only when parse succeeds AND the result is in range; on failure it sets `isInvalid = true` and does NOT mutate `value` (so the last-valid value survives). `.onChange(of: focused)` falling to false with `isInvalid` true triggers the snap-back: `rawText = format(value)` + clear `isInvalid`. `.onChange(of: value)` keeps `rawText` in sync with externally-driven changes (Stepper clicks, programmatic updates) but ONLY when not focused (avoid stomping the user's mid-edit input). Red glow: `.overlay(RoundedRectangle(cornerRadius: 4).stroke(Color.red.opacity(isInvalid ? 0.85 : 0), lineWidth: 1.5))` with `.animation(.easeInOut(duration: 0.15), value: isInvalid)`. `Stepper(in: range, step: step)` clamps natively — its writes always land valid. **Frame:** 72×22 with explicit `.font(.system(size: 12))` (PR 38 widened from the original 56×18; the original was tuned for 5-char feed values like `15.00` and overflowed on 4-digit fcut like `1650` or 5-char feed like `12.00`, triggering a SwiftUI TextField vertical-baseline shift symptomatically identical to the `roundedBorder` bezel autosize bug originally fixed in commit `f526544`). `decimals: Int = 2` parameter (callers pass `decimals: 0` for integer-valued fields like fcut).

## libmpv vendoring + linkage

- libmpv is vendored in `Vendor/libmpv/` from `media-kit/libmpv-darwin-build` v0.6.3 (`macos-universal-audio-encodersgpl` variant, universal). Public `client.h` pinned to mpv v0.36.0 (commit `3996724d3fa1c51cc7998f3de2e22e2c99e6d270`), reported API version 2.1. Refreshing the dylibs requires updating both binaries and `client.h` to a matching upstream tag, then bumping the assertion in `LibmpvLinkageTests`. **The `audio-encodersgpl` variant is GPL-licensed** (FFmpeg built with `--enable-gpl`) — RP Player's MIT source license is unchanged, but the bundled `.app` binary distribution is subject to GPL terms (must provide source on request). The previous `audio-default` variant was LGPL but shipped only `equalizer` + `abuffer` + `aresample` filters; PR 35's parametric EQ needs `volume` / `lowshelf` / `highshelf`, and the future crossfeed PR needs `crossfeed` — all only present in `encodersgpl`. Total dylib bundle is now 15 files (~40 MB) vs the prior 10 (~16 MB) — adds `libfftools-ffi`, `libogg`, `libvorbis`, `libvorbisenc`, `libvorbisfile` as transitive deps.
- `RPSmoke` and `RPPlayerTests` link libmpv with two `@loader_path`-relative rpaths baked in (3-deep for executables, 6-deep for xctest bundles). No `DYLD_LIBRARY_PATH` is needed for `swift test` or `swift run RPSmoke`. PR 15's `.app` packaging will install dylibs under `Contents/Frameworks/` and use a single `@loader_path/../Frameworks` rpath.
- All vendored dylibs use `@rpath/<name>.dylib` install names. Verify after refresh: `otool -D Vendor/libmpv/lib/*.dylib` — every line after the path must read `@rpath/<name>.dylib`. If a future upstream rebuild ships absolute or `@executable_path/...` install names, rewrite via `install_name_tool -id` before committing.

## libmpv concurrency

- `MpvPlayerEngine` runs a single detached event-pump task that calls `mpv_wait_event` with a 0.5s timeout in a loop. Pump exits when `mpv_terminate_destroy` triggers `MPV_EVENT_SHUTDOWN` or when the actor cancels the task. Shutdown ordering: `mpv_wakeup → await pumpTask → mpv_terminate_destroy → emit synthetic .shutdown → finish continuations` — `mpv_terminate_destroy` does not reliably wake an in-flight `mpv_wait_event` on the same handle. mpv's client API is thread-safe except for `mpv_wait_event` (only one thread at a time) — the pump is the only caller.
- The pump task can NOT start from inside `init` because Swift 6.2 strict concurrency forbids capturing `self` (even `[weak self]`) into a `Task.detached` during a non-isolated init. Bootstrap pattern: `init` schedules `Task { await self.startPump() }` (an unstructured Task on the actor's executor); `startPump()` then spawns the detached pump. Handle is wrapped in a private `HandleBox: @unchecked Sendable` to cross the boundary.
- `AppDelegate.applicationWillTerminate` blocks the terminate path on `coordinator.shutdown()` via `DispatchGroup.wait(timeout: 2.0)` with awaiting work spawned via `Task.detached`. The `Task.detached` is load-bearing: `applicationWillTerminate` runs on main, and a non-detached `Task { @MainActor in await shutdown() }` would never start because main is parked in `group.wait`. The 2 s cap matches the libmpv pump shutdown budget.
- **Engine playlist surface for gapless playback.** `MpvPlayerEngine` baseline option `prefetch-playlist=yes` is REQUIRED for `loadfile <url> append-play` to actually pre-open the queued URL on mpv's worker thread; without it `append-play` only starts the HTTP after the previous entry ends (no gapless benefit). Three engine methods cover the playlist lifecycle: `queueNext(url:startSeconds:)` runs `loadfile <url> append-play start=<n>` (omits `start=` when nil/<=0); `advanceToQueued()` runs `playlist-next force` (drops the rest of the current entry, jumps to queued — used by `skipForward` past-last when a queued block exists); `clearPlaylist()` runs `playlist-clear` (preserves the implicit current entry per mpv semantics; used by every coordinator state-cleanup site). `MPV_EVENT_START_FILE` is translated by `MpvEventBridge` to `PlayerEvent.fileStarted` — coordinator uses this as the gapless-transition swap signal.

## Composition root

- `AppContainer` (`Sources/RPPlayer/App/`) is the composition root. `init(...)` is the test seam (pass stub collaborators directly); `static func live() throws` does production wiring (`JSONConfigStore`, `MpvPlayerEngine`, `KeychainCookieProvider`, `HogModeController`, etc.). `AppDelegate.init(containerFactory:)` defaults to `{ try .live() }`; tests override with stub-built containers. `Noop*` fallback types live as `private` declarations at the bottom of `AppContainer.swift`.
- `AppContainer.live()` swallows every recoverable construction error (libmpv init failure → `NoopPlayerEngine`, JSON config open failure → `NoopConfigStore`, album-art cache directory failure → `NoopAlbumArtCache`). The `throws` is reserved for future non-recoverable cases. `AppDelegate.applicationDidFinishLaunching` calls `preconditionFailure` if `live()` throws.
- `AppContainer.runOnLaunchTasks()` fans out via `withTaskGroup` so post-launch work items (notification authorization request + `StartupAuthProbe.run`) run concurrently. Sequential execution would block `StartupAuthProbe` behind `UNUserNotificationCenter`'s first-launch permission dialog on a bundled `.app`.

## Coordinator playback (gapless model, PR 31)

- **Data model: `queue: [GaplessSong]`.** Each song from `api/gapless` is a self-contained file URL with its own `cue` (ms), `duration` (ms), `event_id`, `type` (M/P), `slice_num: Int`. Block boundaries dissolve at the data layer — promo songs are inline-mixed with `type=P`, `update_history=false`. `queue[0]` = currently playing; `queue[1]` = queued in mpv via `loadfile <url> append-play` (1-ahead, same pattern as PR 28). `queue[2..]` = future, in-memory only for cheap skip + Upcoming display + thinness check.
- **Boundary advance via `MPV_EVENT_START_FILE` + mpv path source-of-truth** (post-smoke-test rewrite). Every `.fileStarted` is handled by `syncQueueHeadFromMpv()`: read `engine.currentPath()` (mpv's `path` property), find that URL in `queue`, drop everything before it (firing finish telemetry for skipped songs), update `lastStartedEventId = queue[0].eventId`, emit NowPlaying, fire start telemetry, queueNext for new `queue[1]`, kickRefetch if `queue.count < 3`. Redundant `.fileStarted` events for the same song dedupe via `lastStartedEventId == head.eventId` check. Solves the bug where mpv firing two events around state transitions (auto-advance + replace) made the UI display one ahead of audio. Initial sync (lastStartedEventId nil → first observation) skips the queueNext re-issue since `play()` / `handleSongPlaybackError` / `fileEnded(.eof)` recovery / `skipForward` sync-refetch all already issued queueNext for `queue[1]` immediately after their `engine.play`.
- **`kickRefetch` race-guard.** Captures `currentChannelId` AND `queue.first?.eventId` snapshots before the `await api.gapless`. After the await, re-checks BOTH; discards the result if either changed (channel-change race, or boundary cross during the network call). On success: filter `response.songs` to `eventId > queue[0].eventId`, then `queue = [queue[0]] + newSongs`. Single policy handles overlap (server returns from current cursor → filter strips queue[0] → append), gap (server returned later events → tail replaced), and lag (server returned older events → empty result → next boundary cross retries).
- **Skip behavior.** `skipForward`: when `queue.count >= 2`, fire `update_history` for the skipped song with shortened playtime, then `engine.advanceToQueued()` (`playlist-next force`). The subsequent `.fileStarted` drives state. When `queue.count < 2`, synchronous refetch + `engine.play(queue[0])`. Failure surfaces "Cannot skip — try again" via `errorsContinuation`.
- **Long-idle resume.** `resume()` after `pausedFor ≥ 59 * 60` no longer cancels the paused song. New flow: cache-probe `queue[0]` (miss → legacy refetch+restart fallback that wipes `queue / currentResponse / lastStartedEventId / currentPositionSeconds / current / pausedAt / pausePositionMs` + calls `play(channelId:)`); `engine.resume()` (mpv unpauses queue[0]; queueNext'd queue[1] still in mpv playlist); fire `updateHistory(pauseFlag: true)` telemetry via `Task.detached`; reset `pausedAt = nil` + `pausePositionMs = 0`; truncate `queue` to `prefix(2)`; cancel `downloaderTask` + fire-and-forget `Task { await cache.cancelInFlightDownloads() }`; `kickRefetch()` for background catch-up. `kickRefetch` snapshots both head and tail eventIds, filters response by `> tailEvent`, merges as `self.queue + filtered` so the preserved prefix stays and backend-current songs append as the new tail. Boundary advance from queue[1]→queue[2] is the silent catch-up jump. Short-idle (`< 59 min`) branch is identical minus the truncate / refetch / downloader-cancel triplet. PR 30 stall watchdog deleted (sole arm site removed; unreachable failure mode with local file:// playback).
- **Per-song error recovery.** `handleSongPlaybackError(code:)` (replaces `advancePastUnplayableBlock`): for mpv per-song-fatal codes (currently `-16`), drop `queue.removeFirst()`, advance via `engine.play(queue[0])` if available, else refetch + retry. `consecutivePlaybackFailures` caps at 3 — after 3 consecutive song failures, escalates to `handlePlaybackError` (catastrophic). `.fileLoaded` resets the counter. Catastrophic codes (`-14` device-unavailable, etc.) still go through `handlePlaybackError` directly.
- **`PlayListSong → GaplessSong` shim is gone.** Task 5 swapped `NowPlaying.song` to `GaplessSong` end-to-end. View models read covers via `coverLarge ?? coverMedium`, ratings as `Int` (0 = unrated). `PlayListSong` stays in the codebase only for the notification-click `info → PlayListSong` recovery path via `SongRegistry`; `PlayListSong.init(from: GaplessSong)` extension bridges `NotificationCoordinator.handle`.
- **No client-side stale-block detection.** PR 24's `BlockSongs.isStale` recovery is gone — gapless cursor + per-song self-contained URLs make the failure mode unreachable. If the backend cursor lags, gapless returns from where it thinks we are and each song plays correctly start-to-end with its own `cue`.
- **Bitrate is pull, not push.** Unchanged from prior PRs. `LivePlaybackCoordinator` takes `bitrateProvider: @Sendable () async -> Int` and calls it at the top of `play(channelId:)` and inside `runRefetch`. `AppContainer.live()` wires it to `store.settings.bitrate`.
- **Lazy event-subscription in `play()`.** Unchanged. `await ensureEventSubscription()` runs at the top of `play()` so the coordinator's continuation is registered before the engine fires events.
- **Engine playlist surface (PR 28-era).** `MpvPlayerEngine` baseline option `prefetch-playlist=yes` is still required so `loadfile <url> append-play` actually pre-opens the queued URL on mpv's worker thread. `engine.queueNext(url:startSeconds:)` / `engine.advanceToQueued()` / `engine.clearPlaylist()` / `PlayerEvent.fileStarted` are all retained from PR 28; the gapless coordinator just drives them differently.
- **Telemetry types.** `slice_num: Int` in `GaplessSong` but `update_history` / `update_pause` take `String?`. Conversion at telemetry call sites: `String(song.sliceNum)`. Telemetry only fires when `song.updateHistory == true` (gapless field; promo songs return false).
- **`positionUpdates: AsyncStream<Double>`.** Now per-song-relative (was: block-relative). Each song is its own file; `currentPositionSeconds` resets to 0 on every `.fileStarted` boundary advance and on initial `play()` (cue is ignored — we always start from 0).

## Coordinator playback — pre-downloaded files (PR 32)

- **Motivation.** `prefetch-playlist=yes` only pre-opens the queued URL (TCP + headers) — it does not pull body bytes ahead. Per mpv#6437, the queued demuxer waits until the current file finishes before streaming the next song's audio. On HTTP that produces a multi-hundred-ms boundary gap that no mpv option closes: `audio-stream-silence=yes` would bypass `ao_reset()` but doesn't help when next-file body bytes haven't arrived; `audio-buffer` only widens the underrun window. The fix is to convert HTTP into local-file playback: download each gapless song to disk before handing mpv the URL.
- **Cache shape.** `LiveSongFileCache` (actor, `Sources/RPPlayer/Playback/SongFileCache.swift`) keyed by `SHA256(gaplessUrl) + "." + URL.pathExtension`. Directory `ConfigPaths.songFileCacheDirectory` = `~/Library/Application Support/RP Player/SongFileCache/`. In-flight dedup via `[filename: Task<URL?, Never>]`. **LRU cap `maxFiles=10` (default, configurable via `init(maxFiles:)`).** After every successful write `evictOldestIfNeeded()` sweeps the directory by `contentModificationDate` and removes oldest entries until count ≤ maxFiles (mirrors `LiveAlbumArtCache` minus the byte-size cap; `localFile`'s cache-hit path already touches mtime so freshly-accessed files stay young). Eviction is ALSO event-driven by the coordinator on every boundary advance + `stop` / `changeChannel` / `shutdown` / `handlePlaybackError`. Worst-case disk footprint at the cap: ~400 MB FLAC / ~30 MB 128k AAC.
- **`cachedFile(for:)` is nonisolated.** The coordinator needs to consult "is this song already on disk?" synchronously inside other actor work. Cheap filesystem probe is safe off-actor. Requires the cache's `directory` property to be `nonisolated let` so the nonisolated method can read it.
- **Sequential download model.** `LivePlaybackCoordinator` holds `downloaderTask: Task<Void, Never>?` — at most one outstanding. `kickSequentialDownload()` cancels any existing task and restarts a fresh walk capped at **2 ahead** via `queue.dropFirst().prefix(2)`, calling `await cache.localFile(for: song)` for each in order. The cap matches the playback need: queue[1] is the next mpv playlist entry (typically already on disk from `play()`'s sync resolve and dedupe-fast via fs-exists), queue[2] is the actual prefetch target, queue[3..] gets downloaded later when the head advances and this kicks again. Without the cap, a fresh 20-song gapless response would download the entire queue in background. Restarted at every queue mutation (bootstrap `play`, `syncQueueHeadFromMpv` advance, `skipForward` sync-refetch, `runRefetch` merge).
- **Bootstrap path** (`play(channelId:)` and `skipForward`'s sync-refetch fallback): `await cache.localFile(for: queue[0])` BEFORE `engine.play(url:)` — so the first song is fully downloaded before it starts. Then `await cache.localFile(for: queue[1])` for the queueNext call. Then `kickSequentialDownload()` walks the rest in background.
- **Boundary advance** (`syncQueueHeadFromMpv` on every `MPV_EVENT_START_FILE`): (1) spawn `update_history` telemetry for dropped songs (existing); (2) spawn a `Task { for song in dropped { await cache.evict(song) } }` so eviction is ordered AFTER the telemetry spawn — the cursor-advanced-at-backend semantics the user asked for; (3) `await cache.localFile(for: queue[1])` → `engine.queueNext(local)`; (4) `kickSequentialDownload()`.
- **Eviction timing.** Files are evicted after the song they correspond to is no longer queue[0] AND the `update_history` telemetry has been spawned. Eviction is fire-and-forget (`Task { ... }`); coordinator does not await its completion. This matches the user-stated intent: "clean up the file once jumped to the next song and the telemetry is sent (cursor advanced at backend)".
- **Failure fallback.** Every cache-resolving call site has `?? URL(string: song.gaplessUrl)`. If the cache returns nil (network failure, disk full, `NoopSongFileCache`), playback proceeds via remote URL. Existing pre-PR-32 gap behavior is the worst-case degraded mode, not a hard error.
- **`NoopSongFileCache`.** Private actor at the bottom of `AppContainer.swift`. Falls back to passthrough URL — `localFile(for:)` returns `URL(string: song.gaplessUrl)` so playback works even if the directory can't be created. `cachedFile(for:)` returns nil. `evict` / `clear` are no-ops.
- **EOF recovery non-blocking pattern (PR 40).** The `.fileEnded(.eof)` handler in `LivePlaybackCoordinator` must NEVER suspend the coordinator's actor on `await songFileCache.localFile(for: next)`. Awaiting the cache blocks on in-flight downloads (the actor's own `downloaderTask` writes the file), so a short song (~5s promo) whose EOF lands before the next song's download completes will queue its own EOF event behind the wait — by the time both unblock, the coordinator's queue can collapse to <2 while mpv has nothing queued, leaving audio silent with the UI stuck on "playing". The pattern: synchronous `cachedFile(for:)` (nonisolated fs probe) at the recovery entry; cache hit → call `engine.queueNext(local)` immediately; cache miss → set a `pendingQueueNextSong` field, emit `.loading` (so the UI reflects reality), and defer the queueNext to `tryQueueNextIfPending(landed:)` — a helper invoked from `kickSequentialDownload` after each download lands. The helper checks whether the just-landed song matches the pending one, fires `engine.queueNext`, clears the pending field, lifts state from `.loading` → `.playing`, and logs `elapsedSinceDeferMs`. The recovery branch also ends with a cascade-protection lift in case the queue collapses to <2 before the queueNext branch can re-defer. This pattern (sync probe + post-download hook for deferred work) generalises to the other 5 `await songFileCache.localFile(...)` call sites in the coordinator — captured in `docs/pr-history.md` § Deferred for a future audit.

## View models

- `MiniPlayerViewModel` is `@MainActor final class: ObservableObject`, NOT `@Observable`. Spawns the coordinator-subscription `Task` from `start()` (called by `MiniPlayerView`'s `.task` modifier on first appear), not from `init` — same Swift-6.2 rule that constrains the engine pump bootstrap.
- `MiniPlayerViewModel.openCurrentSongInBrowser()` and `openAbout()` call `NSWorkspace.shared.open(_:)` directly (no injected closure). `openCurrentSongInBrowser` constructs `https://radioparadise.com/music/song/<id>` from `nowPlaying.song.songId` after `Int(songId) > 0` guard (promo blocks have `songId == "0"`).
- `MiniPlayerViewModel.selectChannel(_:)` guards rapid double-calls with an `inFlightChannelId` token: if a second `selectChannel` lands before the first awaited `coordinator.changeChannel(to:)` resolves, the late completion short-circuits and the second selection wins. Tested via `testSelectChannelSecondCallSupersedesFirst`.
- `NotificationCoordinator` is `@MainActor final class` (not an actor) because it bridges `nowPlayingUpdates` to AppKit / UserNotifications types that are main-thread anchored. Configuration (notifications-enabled flag, channel title, on-disk file URL) is injected as `@Sendable` async closures.

## API client

- `JSONDecoder.rpDecoder` is a shared `static let` (snake_case → camelCase). Use it for all RP API decodes.
- Query items in `LiveRpApiClient` are sorted alphabetically — `StubURLProtocol` test URLs must match this order.
- `Channel.chan` is `String` (live API returns `"0"`, not `Int`).
- `RpApiClient.gapless(channel:bitrate:numSongs:)` is the universal song-list endpoint. Shape: `bitrate=X&chan=N&numSongs=N&player_id=ID` (sorted alphabetically). Cookies attached for favorites support (chan=99). Returns `GaplessResponse` with a flat `songs: [GaplessSong]` array; each `GaplessSong` carries its own `gapless_url`, `cue` (always 0 except when server cursor lags), `duration`, `event_id`, `type` ("M"/"P"), `slice_num: Int`. Inline-mixed promo songs have `type=P`, `update_history=false`, `is_rateable=false`.
- `SongInfo.songId` has a custom `init(from:)` that handles both `Int` and `String` JSON values. `GaplessSong.songId` mirrors the same Int-or-String decoder.
- **Promo song edge case (**`type: "P"`**).** RP serves DJ-talk segments between music songs. Each promo is a single inline song with `song_id: "0"`, `artist: "Commercial-free"`, `title: "Listener-supported"`, short duration (~5s), empty `album` field. `GaplessSong.album: String?` is normalised to nil when the API returns an empty string (custom `init(from:)` does `.flatMap { $0.isEmpty ? nil : $0 }`). Symptom of regression if the normalisation breaks: covers / album lines render as empty rectangles for promo. `PlayListSong.album` is also `String?` for the same reason — kept for the notification-click `info → PlayListSong` recovery path.

## Auth + cookies

- `WKHTTPCookieStoreObserver` callbacks are not `@MainActor` — always call `getAllCookies(_:)` (completion-handler form, macOS 13 compat) on the delivery thread before hopping to `@MainActor`. Do not capture `WKHTTPCookieStore` across actor boundaries.
- `LoginWindowController.rpCookieString` joins **all** `radioparadise.com` cookies (not just the auth trio) once the three required auth cookies are present and non-anonymous. Earlier filtering to just `C_username` / `C_passwd` / `C_validated` broke `api/rate` because the server expects session cookies (PHPSESSID etc.) too.
- `kSecUseDataProtectionKeychain: true` causes `errSecMissingEntitlement (-34018)` in unsigned `swift test` processes on macOS 26 beta (Darwin 25.3.0). Do not add it until the app is codesigned.
- `swift test --parallel` fails on `KeychainStoreTests.testSaveOverwritesExisting` with `errSecDuplicateItem (-25299)` — multiple test processes race on the same keychain account. Pre-existing since PR 3. Workaround: serial `swift test`. Proper fix is to scope each test to a unique keychain account namespace.

## Persistence

- `ConfigStore.changes` is an actor-isolated `async` property (not `nonisolated`) — registration is synchronous within actor isolation to eliminate a race window. `JSONConfigStore` is multi-subscriber-safe: each call to `.changes` returns a fresh `AsyncStream` with a unique UUID continuation; `update` yields to all continuations.

## Album art

- `LiveAlbumArtCache` keys files by `SHA-256(coverPath) + ".jpg"`, not by `songId` (multiple songs share an album). Cap: 20 files / 10 MB. Eviction runs on every successful write, removes oldest by `contentModificationDate`. In-flight de-dup via a `coverPath → Task<NSImage?, Never>` map. Response bodies are validated with `NSImage(data:)` before persisting so a 200 with non-image bytes (HTML error page, partial body) does not poison the cache.
- `MiniPlayerViewModel` only resets `currentArt` when the cover path actually changes. Defense in depth so spurious `NowPlaying` re-emissions (e.g., bitrate observer ticks within the same song) don't cause art to flicker.

## Logging

- `AppLogger` is a `final class @unchecked Sendable` with `setMinimumLevel(_:)` / `setVerbose(_:)` mutators behind an `NSLock`. `AppContainer.live()` flips the threshold based on `AppSettings.verboseLoggingEnabled` (re-flips on every settings change). Verbose ON: file sink captures every API request, every coordinator decision (play / pause / resume / skip / prefetch / swap / song-boundary cross), every engine state transition (file load, format detection, AO open, hog write, audio-device write), every bootstrap step. Default OFF.
- File sink lives at `~/Library/Application Support/RP Player/Logs/RPPlayer.log` via `AppLogger.fileBacked(category:directory:minimumLevel:)`.

## Errors

- `PlaybackCoordinatorError: LocalizedError` provides clean `errorDescription` strings for all five cases (`notPlaying`, `channelNotFound`, `blockHasNoSongs`, `engineError`, `underlying`). View models surface `error.localizedDescription`.

## Notifications

- `LiveNotificationService.init(center:)` has NO default argument. Reason: the eager evaluation of `= UNUserNotificationCenter.current()` throws `NSInternalInconsistencyException` ("bundleProxyForCurrentProcess is nil") on macOS 26 inside unbundled processes (`swift run RPPlayer`). `AppContainer.live()` constructs `LiveNotificationService(center: UNUserNotificationCenter.current())` only when `Bundle.main.bundleIdentifier != nil`, otherwise uses `NoopNotificationService`. PR 15 ships the `.app` bundle and the real path lights up.
- **Notification authorization requires a stable code-signing identity.** Ad-hoc signing (`codesign --sign -`) registers the bundle with `usernoted` under a non-stable identity; `requestAuthorization` returns `UNErrorDomain Code=1 "Notifications are not allowed for this application"` with no user prompt. Fix: sign with any real identity (Apple Development, Developer ID Application, or self-signed cert named `RP Player Dev`). `scripts/make-app.sh` auto-detects whichever is available and falls back to ad-hoc with a warning. Hardened runtime (`--options runtime`) is required at the same time; library validation must be disabled via `scripts/entitlements.plist` so the ad-hoc-signed vendored libmpv dylibs still load. After changing identity, reset cached state with `tccutil reset All com.gvajda.rpplayer; killall NotificationCenter usernoted` then relaunch — the first launch enables the toggle in System Settings → Notifications, but the in-app prompt only fires on subsequent launches.
- **Notification request id format:** `"<UUID>|<songId>"`. `LiveNotificationService.extractSongId(from:)` parses the suffix; the UUID prefix prevents `usernoted` from collapsing duplicate notifications when the same song replays.
- `SongRegistry` (in-memory, 100-song bounded ring buffer keyed by songId) caches every notified `PlayListSong` so notification clicks can recover full metadata without an API round-trip when the app is still running. `NotificationCoordinator.handle` records before notifying.
- `NotificationClickRouter` is the `UNUserNotificationCenterDelegate`. On click it: (a) extracts the songId from the request identifier; (b) if it matches `coordinator.nowPlaying`, opens the main popover; (c) else looks up the song in `SongRegistry`; (d) if missing (post-restart, distant past), fetches via `api/info` and converts to `PlayListSong` via `PlayListSong.init(from: SongInfo)`; (e) on API failure, falls back to opening the main popover. Held strongly on `AppDelegate` because `UN.delegate` is `weak`.
- Past-song popover (notification-click) uses `PopoverController.present(rootView:relativeTo:)` — the same controller class as the main popover. PR 23 removed `PastSongPopoverController` and folded it into the shared base. The shared `PopoverController` is constructed with an `EmptyView` placeholder for the past-song instance and gets its hosted view replaced on every notification click. `PastSongView` renders via the shared `PopoverAlbumArt` + `SongTitleRow` + `AmbientGradientBackground` components — visual changes to one popover propagate to the other automatically. Mutual exclusion is bidirectional: `pastSongPresenter` calls `statusItemController.closeIfShown()` before showing the past popover, and `mainPresenter` calls `pastSongPopoverController.close()` before toggling the main popover. The `PastSongViewModel` is held by `AppDelegate.pastSongViewModel` (not by the controller); both `mainPresenter` and `pastSongPresenter` closures call `viewModel.stop()` on the previous VM before transitioning. **Tradeoff:** outside-click / Esc dismissal of the past-song popover does NOT eagerly stop the VM (one orphaned `for await store.changes` loop lingers until the next interaction terminates it). Bounded leak of ≤1 VM at any time. Cleaner alternative is an `onClose:` callback on `PopoverController.present(...)` — tracked as a follow-up.
